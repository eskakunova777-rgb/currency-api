# Курсы валют через API: кэш и конвертер

Учебное задание курса «Вайб-кодер 2.0», модуль 5 «Работа с API». Выполнены базовый и средний уровни.

Программа берёт курсы валют у бесплатного сервиса [open.er-api.com](https://www.exchangerate-api.com/docs/free)
(без ключа), сохраняет ответ в `currency_rate.json` и сутки читает курсы из файла, а не из сети.
Есть конвертер сумм между любыми валютами из списка сервиса.

## Что внутри

| Файл | Что делает |
|---|---|
| `currency.py` | базовый уровень одним файлом: исправленный скрипт `get_currency_rates`, `save_to_file`, `read_from_file`, кэш на 24 часа |
| `api_client.py` | HTTP: `get_currency_rates(base) -> dict`, проверка кода 200 и поля `result`, понятные ошибки сети и таймаута |
| `storage.py` | файлы: `save_to_file`, `read_from_file`, запись и чтение кэша по базовой валюте, проверка возраста |
| `converter.py` | логика: кэш или сеть, проверка кодов валют по списку `rates`, конвертация с 4 знаками |
| `cli.py` | интерфейс: меню и команды `rates` и `convert` |
| `proverka_kesh.py` | проверка, что конвертация из кэша и из свежего ответа совпадает |

## Установка

Нужен Python 3.10 или новее. В папке проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Из сторонних библиотек нужна только `requests`.

## Запуск

Меню:

```bash
python cli.py
```

Или одной командой:

```bash
python cli.py rates USD
python cli.py convert 100 USD RUB
python cli.py convert 100 EUR GBP
python cli.py rates USD --refresh
```

`--refresh` обновляет курсы, даже если кэш свежий. Базовый скрипт одним файлом: `python currency.py`.

## Как работает кэш

`currency_rate.json` хранит ответы отдельно для каждой базовой валюты:

```json
{
    "USD": {
        "saved_at_unix": 1795150360,
        "saved_at": "2026-11-20 12:52:40",
        "response": { "result": "success", "base_code": "USD", "rates": { "RUB": 82.021771, "...": "..." } }
    },
    "EUR": { "...": "..." }
}
```

- Запись моложе 24 часов читается из файла, в выводе пишется «источник: кэш».
- Записи нет или она старше 24 часов: новый запрос, ответ сохраняется, «источник: сеть».
- Курсы USD не подходят для EUR: у каждой базовой валюты своя запись.
- Если сети нет, но запись есть (даже старая), показываются сохранённые курсы с предупреждением.
- Испорченный файл не роняет программу: он считается пустым и перезаписывается.

## 5 ключевых полей ответа `latest`

Запрос `GET https://open.er-api.com/v6/latest/USD`:

| Поле | Пример | Смысл |
|---|---|---|
| `base_code` | `"USD"` | базовая валюта, относительно которой даны курсы |
| `time_last_update_utc` | `"Fri, 20 Nov 2026 00:02:32 +0000"` | когда сервис последний раз обновил курсы |
| `time_next_update_utc` | `"Sat, 21 Nov 2026 00:17:02 +0000"` | когда будет следующее обновление (раз в сутки) |
| `rates.RUB` | `82.021771` | сколько рублей за 1 USD |
| `rates.USD` | `1` | курс базовой валюты к самой себе, всегда 1 |

Ещё полезно поле `result`: `"success"` или `"error"`, при ошибке рядом стоит `error-type`
(например `unsupported-code`). В ответе на USD 166 валют.

## Примеры вывода

```text
$ python cli.py rates USD

Базовая валюта: USD  (источник: сеть)
Курсы обновлены сервисом: Fri, 20 Nov 2026 00:02:32 +0000
Следующее обновление:    Sat, 21 Nov 2026 00:17:02 +0000
  1 USD = 82.0218 RUB
  1 USD = 0.9107 EUR
  1 USD = 0.7624 GBP

$ python cli.py convert 100 EUR GBP

100 EUR = 83.7260 GBP
Курс 1 EUR = 0.83726 GBP  (источник: сеть)

$ python proverka_kesh.py
100 USD -> RUB: свежий ответ 8202.1771, из кэша 8202.1771  совпадает
100 EUR -> GBP: свежий ответ 83.7260, из кэша 83.7260  совпадает
Итог: всё совпадает
```

Ошибки выводятся одной строкой, без стектрейса:

```text
$ python cli.py rates XYZ
Ошибка: Валюта XYZ не поддерживается сервисом.
$ python cli.py convert 100 USD QQQ
Ошибка: Валюты QQQ нет в списке курсов (166 кодов). Примеры: USD, EUR, RUB, GBP.
$ python cli.py convert abc USD RUB
Ошибка: «abc» не число. Пример суммы: 100 или 12,5.
```

## Проверка ошибок сети

Адрес сервиса и таймаут можно подменить переменными окружения, так проверяются сбои без отключения интернета:

```bash
# нет связи: на этом порту никто не слушает
CURRENCY_API_URL=http://127.0.0.1:9/v6/latest python cli.py rates GBP
# Ошибка: Нет связи с сервером курсов. Проверьте интернет и попробуйте снова.

# таймаут: адрес, который не отвечает
CURRENCY_API_URL=http://10.255.255.1/v6/latest CURRENCY_API_TIMEOUT=2 python cli.py rates JPY
# Ошибка: Сервер курсов не ответил за 2 с. Попробуйте позже.
```

## Расхождения задания с реальностью

1. **`rates`, а не `conversion_rates`.** У open.er-api.com курсы лежат в поле `rates`.
   `conversion_rates` есть у платного варианта `v6.exchangerate-api.com/v6/<ключ>/latest/USD`. В коде используется `rates`.
2. **У `json.dump` нет аргумента `encoding`.** Вызов `json.dump(..., ensure_ascii=False, indent=4, encoding="utf-8")`
   падает с `TypeError`. Кодировка задаётся при открытии файла: `open(path, "w", encoding="utf-8")`.
3. **Проверки `status_code == 200` мало.** На неизвестную валюту (`/latest/XYZ`) сервис отвечает кодом 200
   и телом `{"result": "error", "error-type": "unsupported-code"}`. Поэтому дополнительно проверяется `result`.
4. **Сервис принимает лишние буквы.** Запрос `/latest/USDX` возвращает курсы USD, как будто код верный.
   Поэтому код валюты проверяется в программе: ровно три латинские буквы, а для конвертации ещё и наличие в списке `rates`.
5. **Курсы меняются раз в сутки.** Сервис сам обновляет их раз в 24 часа (`time_next_update_utc`),
   поэтому свежий запрос и кэш почти всегда дают одинаковый результат. Разница возможна, только если между
   сохранением и запросом прошло обновление сервиса.
6. **Четвёртый модуль.** В задании три модуля (`api_client.py`, `storage.py`, `cli.py`). Логику конвертации
   и выбора «кэш или сеть» я вынесла в `converter.py`, чтобы `cli.py` занимался только вводом и выводом,
   а `proverka_kesh.py` мог использовать ту же логику.
